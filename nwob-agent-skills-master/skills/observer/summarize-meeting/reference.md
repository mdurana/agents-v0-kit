# Meeting Input Reference

Format detection and normalization hints for `summarize-meeting` (`/meeting`). Load when classifying input or detecting platform.

---

## Transcript Formats (Platform Detection)

### Google Meet

**Signals:**

- Header contains "Transcript" or "Google Meet"
- `MM:SS` or `H:MM:SS` timestamps before speaker lines
- Pattern: `{timestamp} {Speaker Name}: {dialogue}`

**Example:**

```
Transcript — Sprint Planning
00:01:15 Alex Chen: Let's review the backlog for this sprint.
00:01:42 Jordan Lee: The auth story needs spec updates first.
```

**Normalize:** Remove "Transcript auto-generated" disclaimers; preserve speaker names and timestamps.

### Zoom

**Signals:**

- Header/footer: "Zoom Meeting transcript", "Powered by Zoom"
- WEBVTT-style cues (`WEBVTT`, `-->`) or `Speaker Name:` blocks
- Optional meeting metadata block (topic, host, start time)

**Example:**

```
WEBVTT

00:00:15.000 --> 00:00:22.000
Alex Chen: Let's review the backlog for this sprint.

Alex Chen: Let's review the backlog for this sprint.
Jordan Lee: The auth story needs spec updates first.
```

**Normalize:** Strip WEBVTT timing lines if redundant; unify to `Speaker: text` form.

### Microsoft Teams

**Signals:**

- Footer or header: "Microsoft Teams", "Generated by Microsoft Teams"
- Pattern: `{Speaker} ({timestamp})` or `{timestamp} — {Speaker}`
- Transcript export may include meeting title and organizer

**Example:**

```
Alex Chen (0:01:15): Let's review the backlog for this sprint.
Jordan Lee (0:01:42): The auth story needs spec updates first.

---
Generated by Microsoft Teams
```

**Normalize:** Remove Teams footer boilerplate; preserve speaker attribution.

### Generic Transcript

**Signals:**

- Turn-by-turn dialogue with speaker labels
- Timestamps optional
- No identifiable platform header

**Normalize:** Preserve speaker labels; group consecutive turns by same speaker when summarizing topics.

## Meeting Notes Formats (Input Classification)

### Bullet or Numbered Minutes

**Signals:** Attendee header, dated title, sections like Agenda / Discussion / Actions.

```
Sprint Retro — 2026-07-07
Attendees: Alex, Jordan, Sam

Went well:
- Design package signed off on time

Action items:
- Jordan: Update tasks.md by Friday
```

**Processing:** Structure into schema; validate action owners and dates.

### Retro Format

**Signals:** Went well / To improve / Action items (or Start/Stop/Continue).

**Processing:** Map retro columns to Topics discussed and Action items; preserve sentiment in topic bullets.

### Stakeholder Interview Notes

**Signals:** Narrative paragraphs, no dialogue, problem/solution framing, no timestamps.

**Processing:** Extract themes, decisions, and open questions; do not treat as transcript.

### OneNote / Notion / Confluence Exports

**Signals:** Nested headings, bullets, checkboxes; no speaker-turn dialogue.

**Processing:** Structure by heading hierarchy; flag export artifacts (page links, metadata).

### Email Recap

**Signals:** "Hi team, here's a recap", forwarded thread, inline action bullets.

**Processing:** Extract decisions and actions; redact email addresses in output (use names only).

## Mixed-Input Reconciliation

| Situation | Rule |
| --- | --- |
| Notes list decision; transcript shows debate | Note conflict; prefer transcript for "unresolved" unless notes explicitly state final decision |
| Notes assign action owner; transcript names different owner | Surface in Gaps and conflicts; default to notes unless user clarifies |
| Notes omit topic discussed in transcript | Add topic from transcript; mark action `Source` as `transcript` |
| Duplicate action in both sources | Dedupe; set `Source` to `both` |
| Notes-only input | `Platform`: `n/a`, `Platform confidence`: `n/a` |
| Transcript-only input | Full transcript path; no over-compression beyond schema |

---

## Low-Quality Transcript Signals

Flag in Gaps and conflicts when present:

- `[inaudible]`, `[crosstalk]`, `[unclear]`
- Repeated caption errors or missing speaker attribution
- Large gaps in timestamps suggesting dropped audio

Do not invent dialogue to fill gaps.
