# contract-first-design

Design phase playbook for the `solution-architect` agent (`workflow-orchestration.mdc`).

## Steps
1. Read the Intake artifact and the existing repo. On a brownfield repo also read `docs/agents-v0/architecture.md`, `docs/agents-v0/design/system/context-map.md`, the `docs/agents-v0/onboarding/modules/` documents for the touched modules, and `docs/agents-v0/discovery/endpoints.txt` (an operation the draft adds must not clash with one that exists).
2. When the story adds or changes a `/api/v1/` operation, read the feature contract draft at `docs/agents-v0/design/<feature>/openapi.yaml` authored by `schema-author` (or define it when drafting directly without `schema-author`; do not overwrite an existing draft): one self-contained OpenAPI 3.0 file (no external `$ref`) holding only the paths and components this feature adds or changes. For a single-resource CRUD feature, copy `docs/agents-v0/snippets/openapi-resource-crud.yaml` and replace `<placeholders>` instead of inventing the shape. Operations use `/api/v1/...`, each with a unique `operationId`, a 2xx response, security, `additionalProperties: false` on write request-body object schemas (`security-baseline.mdc` §2 / VAPT F8), and (for POST) an `Idempotency-Key` header parameter. All `operationId`s must appear in `design.md`'s Authorization and Traceability sections. A story with no such operation does not add a draft; `design.md` records `N/A: no /api/v1 operation`. Do not invent a path so the draft will lint. Do not edit the org catalog (`openapi/api-v1.yaml`, or the catalog path in `docs/agents-v0/project-profile.md`; `openapi/<service>-v1.yaml` with `Service roots`) during Design. Build merges an approved draft into that catalog (`workflow-orchestration.mdc`).
2b. When the feature publishes or consumes async messages, add `docs/agents-v0/design/<feature>/asyncapi.yaml` (AsyncAPI 2.x or 3.x): one channel per topic or queue. On 2.x each channel `publish` or `subscribe` message has `x-event-type` or `payload.properties.eventType`. On 3.x each operation (`action: send` or `receive`) message has the same field. Align the messages with the JSON schemas under `docs/agents-v0/design/<feature>/events/`. Skip this file when the feature is REST-only.
3. When the feature publishes or consumes async messages, define event schemas under `docs/agents-v0/design/<feature>/events/` with `eventVersion`; evolution additive; envelope includes `eventId`, `eventType`, `eventVersion`, `timestamp`, `source`, `correlationId`, `data`, `idempotency_key`. A story with no event contract records `N/A: no event contract` in the Events section of `design.md`. A REST draft can exist without this contract.
4. Pick one error envelope per API surface: RFC 7807 (`application/problem+json`) **or** the custom `{success, data/error}` envelope — do not mix without versioning.
5. Add idempotency keys on non-idempotent POST/create/pay/cancel.
5b. Expose only what consumers need: callers come to depend on every observable behaviour, including error text and ordering. Change a published operation additively. Retire a field or operation in two steps: mark it `deprecated: true` with the sunset date in its description, and remove it only in a later change after the consumers named in `design.md` have moved. A breaking change needs a new major version or an ADR.
6. Write `docs/agents-v0/design/<feature>/design.md` from `docs/agents-v0/design/_design.template.md`:
   - **Traceability:** every `AC-n` and NFR of the requirements artifact maps to the operation, event, UX component, or ADR that satisfies it.
   - **Data model:** entities, keys, indexes, volume, retention, PII, and the migration shape (`migration-safety`).
   - **Authorization:** one row per `operationId`: roles or scopes, and the resource rule that proves the caller may touch this `{id}` (BOLA, `security-baseline.mdc` §2).
   - **Failure modes:** per dependency and step, the slow and the partial failure, the behavior, and what the user sees. Name every `Kind: negative` and `Kind: edge` id from the requirements artifact.
   - **Observability** and **Rollout** (flag, deploy order, backward compatibility, rollback).
   A section that does not apply says `N/A: <reason>`.
7. Write an ADR for non-trivial decisions at `docs/agents-v0/adr/<NN>-<slug>.md` with at least two real alternatives and why they lost; name it on the `ADR:` line of `design.md`. For sync HTTP vs async messaging, start from `docs/agents-v0/snippets/adr-sync-vs-async.md`. Status is `Proposed` until the design or architecture gate is approved, then `Accepted`. When the reviewer is skipped, that line is `ADR: N/A: no product decision`. Do not invent a second alternative. An Accepted ADR is not rewritten when the decision changes. Set its Status to `Superseded by ADR <NN>`, leave Decision and Alternatives, write the successor at the next number with Status `Accepted`, and point `design.md` at the successor.
7b. When the requirements artifact says `Material: yes`, record `ARC: docs/agents-v0/design/system/arc-record.md`. If an `Approved` `architecture` row already names that file and the recommendation covers this story, cite it and do not add an `arc` row. If this story changes the recommendation, supersede the accepted pattern ADR (do not rewrite it), point the ARC record at the successor, and add an `arc` row. That row is separate from Design. Fitness functions are closed by `slo-evidence` on the P4 SLO story. `Material: no` skips this step. The No contract shortcut does not apply to a material story.
8. Produce Mermaid diagrams (`flowchart`/`sequenceDiagram`) following `architecture-and-diagrams.mdc` conventions when the reviewer runs (an OpenAPI draft, an AsyncAPI or `events/` contract, a UI, or a public route); place under `docs/agents-v0/diagrams/sequences/<service>.md`. When the reviewer is skipped, do not add a diagram.
9. Do not write a helper brief for the contract draft. `/v0-design` launches `schema-author` before the architect when the story has a `/api/v1` operation. A brief is only for a helper that could not be named until mid-phase.
10. Verify that `design.md`, the ADR, `openapi.yaml` (when present, valid OpenAPI 3.0 and backward-compatible with the catalog), and `asyncapi.yaml` (when present) are complete and satisfy the checklist below.
11. Present the Design gate result and wait for approval before Build when the story has an OpenAPI draft, an AsyncAPI or `events/` contract, a UX spec, a public route other than `/health`, `/ready`, or `/live`, or `Material: yes`. The gate names the feature draft, not a catalog edit. After approval, `design` is recorded in `<feature>.state.json`; later changes are amendments (`/v0-design` Amending an approved design). Otherwise record `design` approval and continue to Build (`/v0-design` No contract). P0-A does not run this skill; `/v0-build` writes that N/A design and Release records the phase.

## Rule-compliance checklist
- [ ] `api-and-events.mdc`: contract-first; `/api/v1/`; idempotency keys; one envelope per surface; event `eventVersion`; pagination contract.
- [ ] Feature draft is `docs/agents-v0/design/<feature>/openapi.yaml`, self-contained. The org catalog is not edited in Design.
- [ ] `design.md`: every AC traced; every `Kind: negative` and `Kind: edge` id named in Failure modes; every operation in the authorization matrix; data, failure modes, observability, rollout written or `N/A: <reason>`.
- [ ] `architecture-and-diagrams.mdc`: DDD boundaries; DB per service; ADR with alternatives; an Accepted ADR superseded rather than rewritten; Mermaid conventions; diagram locations.
- [ ] `project-delivery-core.mdc`: async/messaging/cache justified.
- [ ] `security-baseline.mdc` §2: BOLA — authorized lookup for every `{id}` path, retested as a same-role peer (F8). Non-trivial security names always-on findings F4, F8, F9, F10 in the threat-model notes.
- [ ] `openapi.yaml`, `asyncapi.yaml` (when present), and `design.md` are complete and valid.
- [ ] `Material: yes` cites the ARC record. An `arc` row exists only when this story amended the recommendation.
- [ ] `workflow-orchestration.mdc`: Design gate criteria met; stopped for approval.
