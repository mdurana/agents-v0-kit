# Agentic Delivery Workflow Kit (agents-v0)

An agentic delivery kit for **Cursor**. `scripts/install.sh` copies the core into a target repo. `scripts/install.sh --link` pins a kit commit in `docs/agents-v0/kit-pin` and symlinks `.cursor` and `.agents-v0/ci` instead of copying them.

The kit helps agents build and maintain enterprise-grade systems through a gated lifecycle: **Roadmap → Architecture → Plan** for a new program, then **Intake → Design → Build → Verify → Release**, with optional `/v0-local-release` after Verify, and **Maintain** feeding back into Verify. The stack is the id the user names on the pattern ADR (`Pack: <id>`); a discovery `Stack preference:` line is an input that the ADR may accept or reject, and the roadmap copies that line without installing a pack. `/v0-architecture` writes `.agents-v0/packs/<id>/pack.json` and its rules and skills, and binds it with `activate-stack-pack.sh` after the `architecture` row is approved. Any id is valid once that pack is complete (`pack.json`, `rules/*.mdc`, `implement-service`, `implement-bff`, and a UI manifest when `ui` names an id). Example packs under `core/` are not a closed list. The UI is the manifest's `ui` id when `ui` names an id (`core/ui/react` is the React example). The map of every command, record, and check is [templates/docs/agents-v0/agents-v0-kit.md](templates/docs/agents-v0/agents-v0-kit.md) (installed as `docs/agents-v0/agents-v0-kit.md`). A story with a contract, a UI, or a public route stops at every gate for explicit user approval. P0-A skips Intake and Design and stops once, at Release, unless optional `/v0-local-release` already wrote Intake, Design, Build, and Verify. `bootstrap-greenfield.sh --scaffold-app` extracts the `java` example archive into `app/` only for that example. Another pack's P0-A follows that pack's scaffold skill. An empty `Pack` does not select Java. Build copies the milestone story, writes the N/A design, and proves that shell. A story with no `/api/v1` operation, no UX spec, and no public route pins and continues, unless it is `Material: yes` (a new service, datastore, security boundary, or breaking API); that story still stops at Design. Its Design row is written with the Build approval when the shortcut applies. Approval is never inferred. Evidence is persisted and checked by CI at merge. Delivery uses on-prem GitLab (`.gitlab-ci.yml`, `glab mr create`). Set `CI_PACK_IMAGE` to the pack's `ciImage`.

A feature’s progress is `docs/agents-v0/requirements/<feature>.state.json` (`.agents-v0/scripts/sync-feature-state.sh`). `lastApprovedPhase` comes only from an `Approved` row. `activePhase` plus `activeStatus` (`in_progress`, `awaiting_approval`, or `blocked`) is the phase in flight. `/v0-status <feature>` reads that file: `in_progress` or `blocked` runs the same phase again from files already on disk; `awaiting_approval` waits and does not start the next phase. The user names the feature. The newest state file is not assumed to be the one they mean.

Different features may proceed in one checkout only while each writes its own `docs/agents-v0/requirements/<feature>.md`, state file, and `docs/agents-v0/design/<feature>/`. Design writes the feature contract draft at `docs/agents-v0/design/<feature>/openapi.yaml`. Build merges that approved draft into the org catalog (`openapi/api-v1.yaml` unless the profile names another file). Build, verify, release, and maintain stop when `git status` shows another feature’s code or a shared-file edit that is not this feature’s approved diff. Shared files include `docs/agents-v0/project-profile.md`, the org catalog, `docs/agents-v0/architecture.md`, `docs/agents-v0/network.md`, `README.md`, and build or CI files. The feature draft is not a shared file. Ordinary feature work does not rewrite `docs/agents-v0/project-profile.md`. Creating a branch needs explicit user authorization.

## Install

```bash
# install into a target repo (minimal templates; seeds the java example into .cursor)
./scripts/install.sh /path/to/target-repo
# or: ./scripts/install.sh --pack dotnet /path/to/target-repo
# pin the kit instead of copying it (project commits do not include kit files):
./scripts/install.sh --link --path /path/to/this-kit --commit "$(git rev-parse HEAD)" /path/to/target-repo
# greenfield / full starters (copies kit templates and core/<pack>/starters):
./scripts/install.sh --pack <id> --with-starters /path/to/target-repo
# preferred greenfield for Java example (kit + P0 app archive under app/):
./scripts/bootstrap-greenfield.sh --profile app --pack java --scaffold-app /path/to/new-repo
# after editing templates/app/{backend,frontend}, repack the install archive:
./scripts/pack-app-template.sh

# after kit changes: validate, refresh kit-managed files
./scripts/install.sh --update /path/to/target-repo
# offline or air-gapped (no Maven or network): same checks, minus the app-template build test
./scripts/install.sh --update --quick /path/to/target-repo
```

On an Intel Mac, missing host tools named by the bound pack's `hostChecks` are installed with MacPorts when a port exists (JDK 21, Node, npm, Python, Go): `sh .agents-v0/scripts/host-tools-macports.sh` (see `docs/agents-v0/gold-standards.md` after install). The .NET SDK comes from the pack image, not MacPorts. PyYAML uses the same script (`python3 -m pip install pyyaml`, or a `pyXY-yaml` port when Python is from MacPorts).

Seeded only when missing (never clobbered): `README.md` and project templates. Always refreshed on `--update`: `.cursor/` rules, agents, commands, skills, hooks, reference docs, `.agents-v0/ci/*.sh`, `.agents-v0/ci/endpoint_scan.py`, `.agents-v0/ci/packlib.py`, and example packs under `.agents-v0/packs/`. A project pack whose id is not an example is left in place. `--update` keeps the profile `Pack` row. `--link` writes `docs/agents-v0/kit-pin` and symlinks the kit checkout. The profile `Pack` is whatever id has a complete pack (`pack.json`, `rules/*.mdc`, `implement-service`, `implement-bff`, and a UI manifest when `ui` names an id). Example manifests under `core/` are not a closed list.

## Model routing

The kit routes by **role** — Plan, Build, Review, Explore, Debug, Schemas, Docs, Documenter, Orchestrator, and UX Designer — with default Cursor model IDs in [templates/docs/agents-v0/model-routing-matrix.md](templates/docs/agents-v0/model-routing-matrix.md) (installed to `docs/agents-v0/` in target repos). Build (critical) uses the Plan model. Those IDs match `.cursor/model-config.json`. `scripts/install.sh` seeds `.cursor/model-config.json` and runs `.agents-v0/scripts/update-agents-model.sh` to rewrite agent `model:` lines and sync the installed routing matrix from config (or `KIT_MODEL_*` env vars). Run that script again after you change the config. Kit source agents under `core/common/agents/` and `core/<pack>/agents/` keep the matrix defaults.

## Milestone delivery

Milestone programs (P0 Platform Skeleton, P1 Contracts & Data Models, P2 MVP/Core Features, P3 Features 1..N, P4 Hardening, P5 Release Readiness) are manifest-driven: `docs/agents-v0/milestones/<milestone>.md` groups user stories → feature chains, each story running the standard gated chain with approvals in its own artifact. A program that is more than the seeded P0-A story starts from an approved roadmap (`/v0-roadmap`), then `/v0-architecture`; each manifest then records `Roadmap:` and `Architecture: docs/agents-v0/architecture.md`, and each story row has Surface and Size. Story artifacts record `Milestone:` / `Story:` traceability links (`spec-intake` skill). The milestone go/no-go is a `milestone` row in the manifest's canonical `Delivery approvals` table, verified at merge by `.agents-v0/ci/check-approvals.sh` (milestone row) + `.agents-v0/ci/check-milestone.sh` (every story's approvals + evidence). A P4 manifest that names `docs/agents-v0/design/system/slo-evidence.md` also requires that file at `verify` and `release`: each filled SLO row in `docs/agents-v0/design/system/nfr-slo.md` is measured or waived. The ARC record points at that table. Template: `docs/agents-v0/milestones/_template.md`.

## Complex programs


| Need                                       | What the kit provides                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Decompose a large goal                     | `/v0-roadmap <discovery-path>` sequences a discovery file anywhere in the repo. `/v0-architecture` writes the C4-through-operations pack and the ARC record, and `design-reviewer` checks it, before any story. `/v0-plan` then writes the milestone manifests and `docs/agents-v0/milestones/plan.md` (milestone table and story flowchart) from that pack. Approvals are `roadmap`, then `architecture`, then `plan`. Skip list: `workflow-orchestration.mdc` Architecture. `.agents-v0/ci/check-milestone.sh` fails a story that starts Build before the stories it depends on have a Verify approval |
| Several services in one repo               | `Service roots` in the profile Layout (or `services/*/` auto-detected), one catalog per service, CI builds and measures each root                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Parallel features                          | `.agents-v0/scripts/feature-worktree.sh <feature>`: one worktree and branch per feature (needs explicit authorization; hooks ask)                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Numbers that are not self-reported         | `.agents-v0/ci/check-gate-metrics.sh` reads the pack's test, coverage, and CVE reports: executed tests, changed-line coverage under 80% (or `docs/agents-v0/quality-gates.md`) on merge requests for every pack, unsuppressed HIGH/CRITICAL CVEs. Whole-module coverage fails when the pack wires it (Pack `java`: JaCoCo 0.80), when `docs/agents-v0/quality-gates.md` has a Whole-module lines row, or when `MIN_LINE_PCT` is set. A migration or SQL diff must hit the profile database when `DIFF_BASE` is set; H2 does not count. An optional `mutation_ratchet` row checks a mutation report. Pack `java` uses JaCoCo, Surefire, and OWASP. `.agents-v0/ci/check-event-schemas.sh` rejects non-additive event schema changes. `.agents-v0/ci/check-design-contracts.sh` runs OpenAPI, design lock, UX spec, and optional AsyncAPI lint. Testcontainers, Playwright, and k6 jobs are in the CI templates; set `CI_IMAGE_PREFIX` for private registry mirrors (see greenfield onboarding)                                                                                  |
| Fewer approval stops                       | Batch approval of Intake and Design for named, low-risk stories (`workflow-orchestration.mdc`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Bounded effort                             | `Phase attempt budget` (default 8 failed attempts per phase) checked by `.agents-v0/scripts/check-attempt-budget.sh`                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Messaging, E2E, deploy                     | Skills `implement-messaging`, `e2e-perf-testing`, `release-deploy` (profile **Deploy** table)                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Reviewer independence, critical units      | Review role on a stronger model than Build; security-trigger and saga units run on the Plan-role model (`docs/agents-v0/model-routing-matrix.md`)                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Document an existing codebase              | `/v0-onboard` (`codebase-documenter`, `onboard-discovery`): baseline numbers, layout-aware inventories in `docs/agents-v0/discovery/` (endpoints, entities, messaging, config key names, security baseline), cited module documents, as-is architecture and flows. `.agents-v0/scripts/check-onboarding-docs.sh` rejects a citation that does not resolve. Approval is an `onboard` row in `docs/agents-v0/onboarding/report.md` that `/v0-intake` and `/v0-plan` wait for                                                                                                                            |
| Fixes, patches, upgrades, hotfixes         | `/v0-maintain` and `/v0-triage` keep a maintenance note (`docs/agents-v0/maintain/<id>/note.md`) with its own tier, approvals, and evidence; the MR says `Maintain-Note:`. `.agents-v0/ci/classify-change.sh` reads the diff to decide whether the Trivial lane applies (docs-only or version-only, no security surface, schema, or major bump) and a person confirms it. Trivial gets an abbreviated Verify; emergency may merge first and owes Verify by a due date. A feature artifact is no longer accepted for a code change that carries no build or verify evidence               |
| Design you can verify, Build you can check | `/v0-design` writes `design.md` and, when the story adds a `/api/v1` operation, `openapi.yaml` (optional `asyncapi.yaml` for messaging). Prefer Design fill-ins under `docs/agents-v0/snippets/`. A story with no such operation records `N/A: no /api/v1 operation` and skips the draft. `design-reviewer` runs when there is an OpenAPI draft, an AsyncAPI or `events/` contract, a UI, or a public route other than `/health`, `/ready`, or `/live`. The approved design is pinned (`design.lock`); the hash covers `design.md`, the OpenAPI draft, `asyncapi.yaml`, `events/`, the UX spec, mockups, and the cited ADR. A later change is an amendment: `design-reviewer` runs on the design as it stands, you approve the row, then it is pinned again. A changed decision supersedes that ADR (`.agents-v0/ci/check-adr.sh`). A story with none of those pins and continues, unless `Material: yes`; that story cites `docs/agents-v0/design/system/arc-record.md` and stops at Design. An `arc` row is added only when this story changes that recommendation. An `Approved` `architecture` row that names the file covers a story that does not. Otherwise its Design row is written with the Build approval. P0-A skips `/v0-intake` and `/v0-design`: after `--scaffold-app`, Build copies the milestone story and AC-1 through AC-4, writes that N/A design, pins it, and proves the seeded `app/` template. `/v0-build` proves catalog merge, build plan, endpoint auth, and frontend calls against the catalog |
| Release you can trust                      | `/v0-deliver` chains phase commands. `/v0-release` dry-runs `.agents-v0/scripts/check-delivery-gate-local.sh` (linkage, design contracts, build plan, endpoint auth), renders the MR body (`.agents-v0/scripts/render-mr-body.sh`), caps the CI fix loop at three rounds, and records the approving GitLab username. Optional `.agents-v0/hooks/pre-push` runs the same gate when the branch name matches the feature. Regulated teams may archive evidence with `.agents-v0/scripts/export-audit-pack.sh`. `glab mr merge` and `glab mr approve` are blocked; `.agents-v0/scripts/release-notes.sh` updates the changelog |
| Measure the kit                            | `.agents-v0/scripts/delivery-metrics.sh` (Delivery effort)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |




## Validate the kit

```bash
./scripts/validate-kit.sh                       # validate the kit itself (no arguments)
./scripts/validate-kit.sh --target /path/to/target   # also validate an installed target
```

Kit checks: rule frontmatter, cross-references, all sixteen `v0-*` commands, README counts, agent `model:` fields against the routing matrix, Cursor adapter config, required template artifacts (including the P0 app archive and Design snippets), hook classifications, evidence contracts (Build/Verify), the always-on rule size budget (32 KB), the CI template (parses, names only scripts that exist under `.agents-v0/`, Node 22), minimum JaCoCo and ArchUnit versions in the app template, and shell syntax. Target checks: `.cursor/` tree, CI scripts and exec bits, seeded docs, MR template evidence contract, and `!docs/agents-v0/build/` ignore negations. Model availability in Cursor is not verified.

On a target GitLab project, scope `GITLAB_TOKEN` (`read_api`, masked) to the `delivery-approval` environment, replace `@your-team` in `CODEOWNERS`, run `sh .agents-v0/scripts/verify-gitlab-ci-prereqs.sh` before the first pipeline, and set `ENABLE_GITLAB_SAST=1` only when that GitLab provides the SAST template. See [templates/docs/agents-v0/greenfield-onboarding.md](templates/docs/agents-v0/greenfield-onboarding.md). The checks that run at merge are listed in [templates/docs/agents-v0/agents-v0-kit.md](templates/docs/agents-v0/agents-v0-kit.md).
